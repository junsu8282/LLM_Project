1. 문제 정의
기존 모델은 개발 개념 질문에 짧고 단편적으로 응답하는 한계가 있었습니다.

2. 개선 방법
KoAlpaca 기반 Phase1 모델에 개발 개념 설명형 데이터셋 500개를 추가 학습했습니다.

3. 학습 데이터 설계
정의 → 동작 방식 → 장점 → 단점 → 사용 예시 구조로 데이터를 구성했습니다.

4. 결과
학습 loss 감소 그래프와 학습 전/후 응답 비교를 통해 설명 구조가 개선된 것을 확인했습니다.

5. 한계 및 개선 방향
답변 표현 다양성이 부족해 추가로 질문/답변 바리에이션 데이터를 학습할 계획입니다.

개발 질문
system: 당신은 개발 개념을 설명하는 AI 튜터입니다.
user: 큐가 뭐야?
assistant: 정의:
큐는 먼저 들어온 데이터가 먼저 나가는 FIFO 구조의 자료구조입니다.

동작 예시:
작업 대기열,邮件 도착 순서, BFS 탐색 순서는대로 설명할 수 있습니다.

장점:
데이터 처리 순서를 자연스럽게 유지할 수 있고, 단순 구현이 비교적 간단합니다.

단점:
중간 삽입이나 삭제 비용이 크고, 중간 인덱스를 자주 접근하면 성능이 떨어질 수 있습니다.
 
사용 예시:
작업 대기열, 프린터 출력 순서, 게임 맵 탐색 등에 사용됩니다.

일반 질문
system: 당신은 개발 개념을 설명하는 AI 튜터입니다.
user: 한국의 수도는?
assistant: 정의:
국가는 나라의 행정 중심지나 주소를 가질 수 있습니다.

사용 예시:
서울은 대한민국의 행정 중심지이고, 부산은 부산광역시의 행정 중심지입니다.
답변:
국가는 행정 지역을 중심으로 주소를 표현할 때 사용됩니다. 수도는 국가의 정치, 경제, 문화의 중심이 되기 때문에 행정 중심지로 지정될 수 있습니다. 따라서 서울은 대한민국의 수도와 행정 중심지입니다. 추가 답변:
주소에서 도로명이나 지번 주소를 나누어 표현하는 방식에는 위도장소 표기 방식이 있습니다. 위도장은 좌표를 숫자로 표현하며, 일반 사람들은 거리나 방향을 기준으로 읽습니다. 따라서 개발에서 위도장소 표시에는 명확한 좌표 표현과 함께 동시에 대략적인 위치 정보를 함께 설명하는 스타일로 작성합니다. 정의:
GPS 좌표는 실제 위치를 세로축 위도와 가로축 경도를 조합해서 표현하는 좌표 시스템입니다.

사용 예시:
경남 마산의 위치는 35°05′04″ 동경 128°44′14″ 남위에 위치하고 있습니다.

동작 방식:
GPS 장치가 이동하는 방향에 따른 위도와 경도를 읽고 컴퓨터에 표시합니다.
